# 交付报告：历史题材金手指流派修复（线上验证）+ 智谱限流热切换

> 日期：2026-09-02 凌晨 | 项目：途中文枢 AI 小说写作助手 | 交付：线上验证闭环 + 限流应急处理

## 一、背景

用户反馈（截图实锤）：选择「历史 架空历史 两宋元明 穿越 **系统流 签到流** 国运 单女主 扮猪吃虎」+ 书名《永历中兴》，但生成的金手指却是「前世军事知识/历史先知」——纯知识记忆流，**完全无视所选系统流/签到流流派标签**。

## 二、代码层修复（上一轮已完成，本轮验证）

### 根因
1. **idea 步骤历史禁词铁律主动否决流派**：历史题材将「系统/面板/签到/任务/商城」列为绝对禁词，导致系统流/签到流被直接否决 → 金手指方向被锁死为「后世知识/历史先知」。
2. **idea 是下游源头**：灵感方向错了，worldbuilding / powerSystem / characters 全链条跟着错。
3. **powerSystem 流派锚定被跳过**：`isNoSystemGenre`（历史题材）时流派锚定注入被跳过。

### 修复（route.ts）
在 idea 步骤注入 **`_flowSpiritHint`（历史题材·流派精神保留铁律）**：
- **系统流精神** → 知识体系模块化（军事/科技/制度/人才模块）
- **签到流精神** → 阶段性成就奖励（流亡→站稳→新军→江南→北伐→一统，里程碑跃升）
- **面板流精神** → 可量化指标（民心/军心/粮草/科技值/治绩）
- **任务流精神** → 主线目标链驱动
- **总禁词红线**：描述机制时绝对禁止 系统/面板/签到/打卡/任务/商城/抽奖/属性点/技能树/天赋树/数据化/数值化，必须改用历史词汇（知识体系/能力架构/指标/里程碑/收复/攻克）

## 三、本轮线上验证发现的运行时问题：智谱 glm-4.7-flash 高峰限流（429）

### 现象
线上 idea 步骤首次调用 → **HTTP 500「Failed to parse JSON response from AI after all attempts」**；第二次 180s 超时。

### 排查链路（逐步排除）
| 检查项 | 结果 |
|---|---|
| 线上 route.ts MD5 vs 本地 | `fec5540d` = `fec5540d` ✅ 一致 |
| 线上编译产物含新逻辑 | `.next/server/chunks/...f1mj2.js` 含「流派精神」「每收复一城」✅ 部署正确 |
| 直测智谱 key `639e92fb...` | **glm-4.7-flash → 429**（1305 模型访问量过大 / 1302 账户速率限制交替）❌ |
| 直测智谱同 key glm-4-flash | **200**（1.8s）✅ key 本身健康 |
| 直测 OpenRouter minimax-m3:free | **200**（9.5s）✅ |
| 直测 OpenRouter glm-5.2:free | 429 ❌ |

**结论：代码修复正确已生效；500 纯粹是 glm-4.7-flash 模型级限流**（免费池晚高峰访问量过大）。

### 模型质量对照（手动指定模型区分限流 vs 代码）
| 模型 | 状态 | idea 输出质量 |
|---|---|---|
| glm-4.7-flash | ❌ 429 | 最佳（不可用） |

| **minimax-m3:free** | ✅ 200 | **优**：主角「朱由榔」零漂移、卖点「模块知识体系（军事/奇技/制度/人才）」「每一卷阶段性胜利」= 系统流+签到流精神历史化、零禁词 |

## 四、解决方案：限流热切换

将 **4 个质量敏感环节**（idea / worldbuilding / powerSystem / characters）的默认模型从 `glm-4.7-flash` 临时切换为 **`minimax/minimax-m3:free`**（OpenRouter 免费档，已验证可用 + 质量达标）。

三表同步：
1. `route.ts _STEP_MODEL_MAP`（**权威表**，决定真实调用）
2. `step-model-config.ts` QUALITY_FIRST / COST_FIRST
3. `wizard.tsx _STEP_MODEL_MAP_FRONTEND`
