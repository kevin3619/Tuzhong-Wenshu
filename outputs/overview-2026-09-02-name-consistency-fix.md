# 主角姓名一致性 Bug 修复报告（v2026-09-02）

## 一、背景

用户反馈：输入主题「**程序员南明诺 附身桂王世子朱由榔**」（历史/架空历史/两宋元明/穿越/系统流/签到流/国运/单女主/扮猪吃虎，书名《永历中兴》），灵感创作（idea）步却生成主角名「**朱慎之 / 唐阳 / 陆承渊**」——无视输入中明确给定的「南明诺」（穿越者现代名）与「朱由榔」（附身对象/历史人物名）。

## 二、根因分析

| # | 根因 | 说明 |
|---|------|------|
| 1 | **提取源缺失** | `_userProtoName`/`_userModernName` 只从表单 `protagonistSettings`（身份背景+详细设定）读取；用户把姓名写在**主题输入框**（`keywordsStr`/`input`）→ 提取不到 |
| 2 | **正则顺序缺陷** | 现代名旧正则只支持「姓名，职业」（如「雨田诺，21世纪程序员」），不支持「程序员南明诺」这种**职业在前**格式 |
| 3 | **无后处理硬校验** | idea 步「原样保留铁律」仅为 prompt 软约束，parseJSON 后无强制校验兜底，模型自由发挥时无法拦截 |
| 4 | **tagline 修复链再漂移** | 「现代灵魂XX魂穿」错误格式修复链中 `_modernName` 只取表单名，为空时跳过修复或走 LLM 随机生成（可能再漂移） |

权威名链路：`enforceStageConsistency`（L1644）依赖 `idea.protagonistName` 作兜底权威源，idea 步名字一旦漂移，下游全部对齐漂移名 → **必须从源头（idea 步）锁定**。

## 三、修复方案（route.ts 共 5 处）

### ① 人名提取（L12847-12872，新增）
从 `input + keywordsStr + genre` 提取两种名字：
- **现代名**：`(职业词)(2-4字姓名)` 格式，lookahead 到动词/标点/空白截断（防「南明诺附身」被吞）
  - 「程序员南明诺」→「南明诺」
- **附身对象名**：`附身/夺舍/魂穿到/穿越成/重生为` 引导片段 → 剥离身份词（世子/桂王/皇帝…）、国号朝代词（三国/明朝/大明…）、连接词 → 取末尾 2-4 字块
  - 「附身桂王世子朱由榔」→「朱由榔」
- **防误提取**：banned 词表（身份词/泛化词/朝代词/「穿越小说」类）；附身片段排除集含 `\s`（空格截断）；表单指定名优先（`_userProtoName` 存在时输入提取名作废）
- 旧格式「姓名，职业」正则保持只跑表单源 `_idFull`（避免「穿越小说, 程序员」误提取）

### ② Prompt 锚定（L12878-12900）
`_protagonistSettingsHint` 构造条件扩展 + 追加「【输入主题指定】主角姓名必须严格使用X，绝对禁止另编朱慎之/唐阳/陆承渊」条款。

### ③ 硬校验（L13482-13510，parseJSON 后）
权威名锁定：
- `_canonIdeaProto = _userProtoName || _inputProtoName`（表单 > 输入文本）
- `_canonIdeaModern = _userModernName`
- AI 输出不一致 → 强制替换 + `_deepReplaceName` 全字段同步（含数组字段 coreSellingPoint 等）；输出缺字段 → 补写

### ④⑤ tagline 修复链（L13990+ / L14090+）
`_modernName`/`_modernNameFixed` 来源优先取**已锁定的 `result.modernName`**，避免「现代灵魂朱由榔魂穿」修复时再走 LLM 随机生成新名。
